# Race to 100 Website

This folder is the source of truth for the Race to 100 marketing, support, and
legal website.

## Hosting topology

- Canonical site: `https://raceto100.app/` on Cloudflare Pages.
- Pages project: `race-to-100`.
- Git source: `Meloforms/race-to-100-app`, production branch `main`.
- Framework preset: None.
- Build command: empty.
- Build output directory: `website`.
- Root directory: empty.
- Default production hostname: `https://race-to-100.pages.dev/`.
- Legacy site: `https://meloforms.github.io/` remains available for links
  generated by already-installed app versions.

Pushing `main` triggers the Cloudflare Pages deployment automatically. Do not
add a `CNAME` file: Cloudflare manages the custom-domain DNS association in the
Pages dashboard.

## Public routes

- `/`: marketing one-pager.
- `/support`: support and contact information.
- `/privacy`: Privacy Policy.
- `/terms`: Terms of Service.
- `/delete-data`: account/data deletion instructions.
- `/d/`: Daily Duel landing page. This route is intentionally `noindex` because
  shared URLs may contain public social-proof query parameters.
- `/app-ads.txt`: AdMob publisher verification.
- `/robots.txt` and `/sitemap.xml`: crawler configuration.

Cloudflare Pages redirects `.html` routes to their extensionless equivalents.
The tracked `.html` files and relative links are retained so the legacy GitHub
Pages copy also works.

## Cloudflare Pages deployment

No manual build or upload is required. Review and push the website change to
`main`; Cloudflare builds from the `website` directory and publishes a unique
deployment URL plus the default production hostname at
`race-to-100.pages.dev`.

Before attaching or changing the custom domain, verify the new production
deployment and the backend CORS/public-invoker changes. Do not begin the domain
cutover while the live click endpoint still returns IAM `403`.

## Canonical domain cutover

Use only `raceto100.app` as a Pages custom domain. Do not add `www` to Pages;
it is a redirect-only hostname.

1. In **Workers & Pages → race-to-100 → Deployments**, confirm the migration
   commit is the successful production deployment and open
   `https://race-to-100.pages.dev/`.
2. Open **Custom domains → Set up a domain**, enter `raceto100.app`, select
   **Continue**, review the generated record, and select **Activate domain**.
3. Wait until the custom-domain status is **Active**. Under
   **raceto100.app → DNS → Records**, verify Cloudflare created a proxied apex
   CNAME pointing to the exact Pages production hostname. Do not create this
   CNAME manually before associating the domain in Pages.
4. Under **SSL/TLS → Edge Certificates**, confirm the certificate is active and
   enable **Always Use HTTPS**. Do not enable HSTS during this migration.
5. At account level, open **Bulk Redirects** and create a list named
   `race_to_100_domain_redirects` with this entry:
   - source: `www.raceto100.app`
   - target: `https://raceto100.app`
   - status: `301`
   - enable **Preserve query string**, **Subpath matching**,
     **Preserve path suffix**, and **Include subdomains**.
6. Continue to Redirect Rules, create
   `redirect_race_to_100_domains` from that list, and select
   **Save and Deploy**.
7. Under **raceto100.app → DNS → Records**, add a proxied `A` record named
   `www` with value `192.0.2.1` and TTL Auto. This documentation-only address
   lets the proxied request reach the redirect rule; it is not an origin.
8. Run the full post-cutover validation matrix below before changing Remote
   Config, store metadata, or publishing a binary that creates new-domain Duel
   links.

Rollback:

1. If only the website revision is faulty, use **Workers & Pages →
   race-to-100 → Deployments** to roll back to the prior successful deployment;
   leave DNS unchanged.
2. To undo the domain association, first delete the generated Pages apex CNAME
   under **DNS → Records**, then remove `raceto100.app` under the Pages
   project's **Custom domains**.
3. To undo `www`, delete its dummy `A` record and disable or delete
   `redirect_race_to_100_domains`; remove the redirect list if it is unused.
4. The project remains reachable at `race-to-100.pages.dev`, and the legacy
   GitHub Pages site remains unchanged.

## Legacy GitHub Pages mirror

Existing app versions continue to generate
`https://meloforms.github.io/d/?...` links. Keep that site operational through
the supported lifetime of those versions.

Do not refresh the legacy mirror until the canonical domain has passed HTTPS
and route validation. The mirrored HTML deliberately points canonical metadata
and homepage sharing at `raceto100.app`, so an early sync would publish broken
new-domain links.

After that gate passes, clone the separate mirror into a fresh temporary
directory, verify its remote, and copy this folder without deleting unrelated
files:

```bash
LEGACY_MIRROR_DIR="$(mktemp -d)"
git clone git@github.com:Meloforms/meloforms.github.io.git \
  "$LEGACY_MIRROR_DIR/meloforms.github.io"
cd "$LEGACY_MIRROR_DIR/meloforms.github.io"
test "$(git remote get-url origin)" = \
  'git@github.com:Meloforms/meloforms.github.io.git'
rsync -av --exclude=.git \
  /Users/bas/Desktop/Projects/Apps/Race-to-100/website/ \
  "$LEGACY_MIRROR_DIR/meloforms.github.io/"
git status --short
```

Review the mirror diff before committing or pushing it. This migration does not
automatically update that separate repository.

The tracked `.nojekyll` file exists only for this legacy GitHub Pages mirror.

configuration:

```js
window.RaceTo100Site = { APP_STORE_URL };
```

The primary CTA reads `Download on the App Store`, and the availability copy
states that the app is available for iPhone and iPad. The homepage share button
deliberately shares `https://raceto100.app/` rather than the current browser
URL, preventing preview or `www` hostnames from leaking into shared links.

## Daily Duel links

New app builds generate:

```text
https://raceto100.app/d/?c=<token>&n=<name>&f=<countryCode>&t=<elapsedMs>&d=<dailyId>
```

`d/index.html` renders user-controlled display names with `textContent`, never
`innerHTML`. It sends best-effort aggregate store-click tracking to the public
Firebase HTTP function, but tracking failure must never block store navigation.

The backend must allow both exact website origins:

- `https://raceto100.app`
- `https://meloforms.github.io`

Do not add Universal Links, Android App Links, or an in-app challenge route as
part of this website migration.

## Assets and fonts

Website images use stable filenames under `assets/screens/`. Replace those
files without changing HTML paths when screenshots are refreshed.

Inter and Unbounded are self-hosted under `assets/fonts/` from the app's
bundled font assets. Their SIL Open Font License notices are retained in
`assets/fonts/OFL.txt`. Do not reintroduce runtime Google Fonts requests without
a privacy and performance review.

The current social image is the absolute canonical URL
`https://raceto100.app/assets/screens/home.png`. A future dedicated 1200×630
share image can replace that URL without changing page structure.

## Domain-coupled app configuration

The website deployment alone does not complete the migration:

- Firebase `trackDuelStoreClick` must be publicly invokable and return matching
  CORS headers for both canonical and legacy origins.
- App source uses the canonical website/legal URLs and
  `https://raceto100.app/d/` for Daily Duel links. Remote Config version 14
  updates generated share links without requiring an urgent binary solely for
  the domain cutover.
- Firebase Remote Config `share_link_url` is `https://raceto100.app/` as of
  template version 14. Existing versions that cached the previous value remain
  supported by the legacy mirror.
- The public iOS App Store listing is
  `https://apps.apple.com/be/app/race-to-100-dice-puzzle/id6775581657`;
  future store-metadata changes remain release-gated.

## Validation

Before merge:

```bash
rg -n 'meloforms\.github\.io|fonts\.googleapis\.com|Placeholder:' \
  website/*.html website/d/index.html
git diff --check
```

The first command should return no matches.

After the Pages deployment, inspect statuses without following redirects:

```bash
for route in / /support /privacy /terms /delete-data /d/ \
  /robots.txt /sitemap.xml /app-ads.txt; do
  curl -sSI --max-redirs 0 "https://race-to-100.pages.dev${route}" |
    sed -n '1p;/^location:/Ip;/^content-type:/Ip'
done

test "$(curl -fsS https://race-to-100.pages.dev/app-ads.txt)" = \
  'google.com, pub-7570956149985965, DIRECT, f08c47fec0942fa0'
curl -sSI --max-redirs 0 https://race-to-100.pages.dev/contact.html
curl -sSI --max-redirs 0 https://race-to-100.pages.dev/not-a-real-page
```

Expected: the public extensionless routes return `200`, `/contact.html`
redirects to `/support`, and the missing route returns a real `404` page.

The default Pages hostname is intentionally not in the function's CORS
allowlist, so its store-click request is not an end-to-end telemetry check.
Before domain activation, test the backend separately with both exact allowed
`Origin` headers and confirm an unrelated origin receives no CORS permission.

After domain activation, require all of these gates:

- `https://raceto100.app/` returns `200` without a redirect.
- `http://raceto100.app/` redirects to the same HTTPS path.
- `.html` policy URLs redirect to their extensionless canonical routes.
- `https://www.raceto100.app/d/?c=demo&n=climber_AB12&f=BE&t=42000&d=2026-06-23`
  returns `301` to the identical apex path and query.
- Privacy, Terms, Support, Delete Data, Duel, assets, crawler files, and
  `app-ads.txt` all load over HTTPS.
- `app-ads.txt` returns the exact approved line as plain text.
- Complete legacy URLs at `https://meloforms.github.io/` still load.
- A valid-shaped unknown-token Duel click returns the documented opaque `204`.

Inspect redirects explicitly with `curl -sSI --max-redirs 0`; use `curl -fsSL`
only after the status and `Location` headers have been checked.
